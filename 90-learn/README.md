# 学习与交流（90-learn）

这条线不是工作速查，也不是案例库，用途只有一个：**把公开前沿知识转成你的能力**。

## 铁律

1. **只收公开可得信息**：厂商公开文档、开源驱动源码、内核邮件列表、会议论文与 slides。
2. **自研平台私有事实一律不入库**：寄存器偏移、固件版本、时序参数、内部架构都不进这个仓库。涉及自研时只写「公开可类比的机制」，具体数值留空。
3. 每条都要能追到来源 URL 与日期；无来源的写成「推测」。

## 节奏

| 时间 | 谁 | 干什么 |
|---|---|---|
| 工作日 | 我 | 收集前沿材料 → 拆成讲解卡 + 题目，落到 quiz/ 与对应层级 |
| 工作日 | 你 | 读本周两个主题，先自己作答（不许先看答案） |
| 周六上午 | 双方 | **交流**：这里不叫考核。先互相提问，再就分歧头脑风暴，我把你的原话答案按评分点判 |
| 周日 | 我 | 只补错题，把缺口写回 quiz 与 weak-points.md |

「交流」的规矩：你可以反问，也可以挑我的答案——能把我问住才算你真的通了。每场交流必须留下**至少一个未解决的问题**写进库里，那是下一次的起点。

## 三个层级（题目标 L1/L2/L3）

- **L1 概念**：名词与机制是什么。例：SMMU 的 SVA 是什么，和 IOMMU 是一回事吗。
- **L2 机制**：为什么这样设计、怎么实现、替代方案为什么不选。例：门铃写之前为什么需要 barrier，ARM 上 MMIO 写序到底保证了什么。
- **L3 现场**：给现象判根因、给约束做取舍。例：fence 永不完成，30 分钟内你怎么定位，先看哪三处。

拔高发生在 L2 和 L3 —— L1 只是入场券。周六交流按 L1:L2:L3 = 2:5:3 抽。

## 目录

| 路径 | 内容 |
|---|---|
| plan.md | 摸底安排、本周两个主题、后续轮次排期 |
| roadmap.md | 知识地图 + 掌握度矩阵（0 未学 / 1 听过 / 2 会答 / 3 能教人） |
| quiz/ | 题库，一主题一文件，每题带评分点与追问 |
| logs/ | 每次交流记录 YYYY-MM-DD.md（问题、你的原话答案、判定、缺口、未解决问题） |
| weak-points.md | 反复错的点，按错次排序，下次优先抽 |
| sources.md | 前沿来源登记（标题、URL、日期、可靠度、复核状态） |

## 题目卡格式（写进 quiz/ 时照抄）

```
### <前缀>-<编号> <一句话题干>
- 层级: L1 | L2 | L3
- 评分点: 3-5 条，答中几条算过
- 标准答案: 先给结论再给机制，带 file:line 证据
- 追问: 答对后加深的那一问
- 来源: URL + 日期
```
